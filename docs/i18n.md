# Mimshel i18n (en / ru / zh / zh_TW) — branch `i18n-en-ru-zh` (v2)

Upstream Mimshel hardcodes Russian UI strings in 30+ Rust files, with no
language setting and no gettext. Its locale handling only affects
`.desktop` app names and text shaping, not its own menus.

This branch adds a minimal, maintainable multilingual layer — deliberately
**not** a full gettext port, and **not** a claim that the whole UI is
translated.

## Architecture

- `crates/core/src/i18n.rs` — one static table, `key -> (en, ru, zh, zh_tw)`.
  Russian strings are the upstream originals, kept verbatim as `ru`.
  `Language::{Auto, En, Ru, Zh, ZhTw}`:
  - Config default in v2 is `en` (user decision 2026-10-27). A config
    file that does not set `look.language` therefore renders in English,
    not Russian, and not by following the locale.
  - `auto` is an explicit opt-in that follows the system locale
    (`LANGUAGE`, then `LANG`, then `LC_ALL`, then `LC_MESSAGES`).
    Locale mapping: `zh_TW` / `zh_HK` -> `ZhTw`; `zh_CN` / `zh_SG` /
    bare `zh` -> `Zh`; `ru_*` -> `Ru`; `en_*` -> `En`; anything else
    (including C/POSIX) -> `En`.
  - An explicit value in config always wins over the locale.
  - Unknown keys return the key itself (visible in review, never blank).
  - Chinese has two columns: Simplified `zh` (e.g. 废纸篓, 文件管理器,
    搜索) and Traditional `zh_TW` (Taiwan wording, e.g. 垃圾桶,
    檔案管理員, 搜尋, 檢視, 視窗, 資料夾). Japanese is out of scope
    (user decision 2026-10-27: Traditional yes, Japanese no).
- `crates/core/src/config.rs` — `Config.language`, parsed from
  `[look] language` in `~/.config/mimshel/config.toml`. If the file does
  not set a lock placeholder or app renames, those defaults follow
  `[look] language` (not just system locale); an explicit placeholder /
  rename in the file always wins.
- Wiring: pure crates keep their upstream Russian defaults and gain a
  `*_lang` / `set_language` variant (`places_lang`, `Section::title_lang`,
  `Dock::set_language`, `FolderView::set_language`, `SearchPanel` /
  `AppsPanel::set_language`, `Center.language`, `MenubarUi` /
  `DesktopUi` / `FolderUi` / `DockUi` / `NotifyUi::set_language`).
  The app layer (`apps/mimshel`) passes `config.language` in, so the
  daemon reloads on `mimshel apply` (service restart) and the terminal
  picks it up when a new window opens. No global mutable locale state.

## Usage

```toml
# ~/.config/mimshel/config.toml
[look]
language = "en"   # or "ru", "zh", "zh_TW", "auto" (default in v2: "en")
```

```sh
mimshel set look.language en    # canonical
mimshel set language zh         # bare alias, same thing
mimshel set language zh_TW      # Traditional Chinese (Taiwan wording)
mimshel set language auto       # explicit opt-in: follow system locale
mimshel set language en         # hot reload, no daemon restart (v2, see below)
mimshel reload                  # same hot reload, e.g. after hand-editing config
```

Invalid values are rejected by `mimshel set`:

```text
✘ look.language: можно: en, ru, zh, zh_TW, auto
```

## Hot reload (v2, no daemon / session / machine restart)

`mimshel set look.language <value>` and `mimshel set look.wallpaper <value>`
no longer restart the service. The `set` command writes the config and
then sends `reload` over the daemon's existing Unix socket
(`$XDG_RUNTIME_DIR/mimshel.sock`); the daemon's main loop re-reads the
config, calls `set_language` on every component, and redraws on the
next flush. The daemon PID does not change.

A second path covers hand-edited config files: the daemon also watches
the config file's mtime (poll every 2 s) and sends itself a `Reload`
message when it changes. Reload only reads the file, so it cannot
retrigger itself. `mimshel reload` is the manual form of the same
message (useful after `--no-apply` sets or hand edits).

What switches immediately on reload:
- Menubar bar, Dock, desktop icons + context menu, folder windows
  (sidebar, title, status bar, context menu), Search / Apps panels
  (next open, and the currently open panel via redraw), notification
  centre (next open), lock-screen placeholder (next lock).
- Wallpaper: if `look.wallpaper` changed, the desktop painter is
  re-triggered and the new wallpaper is applied when its paint
  message arrives (same mechanism as picking a wallpaper in the UI).

What does NOT hot-reload (honest list, do not claim otherwise):
- Already-open terminal windows: their menus were exported over DBus
  at window creation. New terminal windows pick up the new language;
  already-open ones must be reopened (same rule as other terminal
  settings in v1).
- Already-open popups (menubar menu, Control Center, About,
  wallpaper picker): their menus were built at open time. Close and
  reopen them to see the new wording.
- CLI help / `doctor` output: still Russian (see NOT translated list);
  a new CLI process reads the config fresh, but its own strings are
  not in the i18n table.
- `mimshel apply` (plain, without a language/wallpaper-only set)
  still restarts the service, as before. Hot reload is the
  `set language` / `set wallpaper` / `reload` path, not a change to
  every `apply`.

## Translated in this branch (visible UI)

- Menubar bell menu: Do Not Disturb / Notification Settings…
- Dock: Trash name + tooltip, right-click menu (Open, New Window,
  Keep in Dock, Run on discrete GPU, Quit, Empty Trash…).
- Folder / file-manager windows: sidebar section titles (Places /
  Devices), Trash + File System place names, context menu (Open, Open in
  New Window, Rename, Copy, Cut, Move to Trash, New Folder, New Text
  File, Paste, Open Terminal Here), window title (`<folder> - File
  Manager`), status bar (folder/file counts, Free, selected items,
  empty-folder / nothing-found texts).
- Desktop context menu: same folder-menu wording + Arrange +
  Change Wallpaper…
- Terminal window menus: Shell / Edit / View / Window, plus all items
  inside them (New Window/Tab, Close Tab/Window, Copy, Paste, Select
  All, Clear History, Zoom In/Out/Actual Size, Next/Previous Tab),
  and the terminal window title.
- Search / Apps windows: placeholder text (Search).
- Notifications: centre header (Notifications), Clear button, empty
  text (No notifications), Do Not Disturb menu.
- Lock screen: placeholder (Enter password / 输入密码) — via
  `Config.lock_placeholder` default when the file does not set one.
  "Wrong password" and the sentences shown when PAM refuses for another
  reason (too many attempts, expired password or account) follow
  `look.language`; what PAM itself says is shown as PAM wrote it.
- App renames (fresh configs): File Manager, Terminal, Xfce Terminal,
  Text Editor, Settings, System Monitor, Home.

## NOT yet translated (TODO-I18N)

Everything else still shows upstream Russian literals. Do not present
this branch as "fully translated". Known remaining areas, in rough
order of visibility:

- CLI help / `mimshel config` / `doctor` output (`apps/mimshel/src/main.rs`,
  `setup.rs`, `crates/setup/src/doctor.rs`) — still Russian.
- `SETTINGS` descriptions in `crates/core/src/config.rs` — still Russian
  (only the new `look.language` description is in English).
- Control Center tiles and detail panels (Wi-Fi / Bluetooth / Sound),
  calendar month/day names (these already come from system locale in
  `crates/menubar`), About window, wallpaper picker, settings dialogs.
- File-manager size units and date formats (`human_size`, Thunar-style
  status formatting), plural rules beyond folder/file counts.
- Search / Apps window empty states beyond the placeholder, keyboard
  shortcut hints inside other windows.
- All comments and docs in Russian (intentionally left; translating
  comments is not user-visible and would churn upstream diffs).

To translate a new area: add keys to `crates/core/src/i18n.rs::KEYS` +
`t()`, thread `config.language` through the owning UI struct (same
pattern as above), add the key to the "Translated" list here, and add
a test in `i18n::tests` if the string is user-visible.
